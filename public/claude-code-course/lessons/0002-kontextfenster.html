Was Claude auf dem Schreibtisch hat, und was /compact übrig lässt

Das Kontextfenster ist ein Schreibtisch mit begrenzter Fläche. Einiges liegt schon beim Start drauf, beim Arbeiten kommt mehr dazu, und /compact räumt auf. Danach weißt du, was beim Aufräumen bleibt und was verschwindet.

Vorab, aus dem Kopf
Du tippst /compact. Was glaubst du: Muss Claude deine CLAUDE.md danach neu kennenlernen, oder ist sie sofort wieder da? Rate einfach. Die Antwort steht in Abschnitt 6.

1. Was ist das Kontextfenster?

Claude merkt sich nichts von einer Nachricht zur nächsten (das war Lektion 0001). Alles, was es für deine Session wissen soll, steht deshalb in einem einzigen Textstapel, der bei jeder Nachricht mitgeschickt wird. Dieser Stapel heißt Kontext, und der Platz dafür ist das Kontextfenster.

Laut den Docs steckt darin: deine Anweisungen, die Dateien, die Claude gelesen hat, Claudes eigene Antworten und Inhalte, die du im Terminal nie siehst. (Docs: Explore the context window)

Bild: ein Schreibtisch mit begrenzter Fläche. Was darauf liegt, kann Claude sehen. Was nicht darauf liegt, weiß es nicht.

Der Platz wird in Tokens gemessen, das sind kleine Textstücke. Ist der Tisch fast voll, endet deine Session nicht: Claude Code räumt dann von selbst auf, das ist dasselbe wie /compact (mehr dazu in Abschnitt 6).

2. Wo siehst du das?

Tippe in einer laufenden Session /context. Du bekommst eine Übersicht, wie viel gerade belegt ist, sortiert nach Kategorien, dazu Spartipps und die Liste, welche CLAUDE.md- und Memory-Dateien geladen wurden. (Docs: Check your own session) Mit /memory kannst du diese Dateien öffnen und bearbeiten.

Zur Anschauung: In der Beispiel-Session der Docs sind nach etwas Arbeit gut 22.000 Tokens belegt (die Zahlen sind laut Docs nur Beispiele). Deine echten Zahlen siehst du nur mit /context.

Ob die Desktop-App zusätzlich eine eigene Anzeige hat: nicht geprüft.

3. Drei Zeitpunkte

Wichtig ist, wann etwas auf den Tisch kommt:

  1. Beim Start: ein paar feste Dinge liegen schon da.
  2. Beim Arbeiten: alles, was Claude liest, kommt dazu.
  3. Beim Aufräumen (/compact): das Gespräch wird zu einer Kurzfassung, einiges wird frisch hingelegt.

Quelle für alles hier: Docs: Explore the context window

4. Was beim Start schon daliegt

  • Deine Regeln: die globale und die Projekt-CLAUDE.md.
  • Deine Notizen: die Memory (MEMORY.md).
  • Visitenkarten der Skills: nur die Kurzbeschreibung. Der ganze Text eines Skills liegt erst auf dem Tisch, wenn du ihn aufrufst.
  • Namen der Werkzeuge von angeschlossenen Diensten (MCP).

Es gibt Grenzen, wie viel davon geladen wird. (Docs: Memory) Diese Grenzen gelten:

DateiGrenze
Memory (MEMORY.md)200 Zeilen
CLAUDE.mdZiel: unter 200 Zeilen

5. Was beim Arbeiten dazukommt

  • Jede Datei, die Claude liest. Sie bleibt, bis du aufräumst.
  • Regeln, die nur für bestimmte Dateien gelten (Frontmatter paths:) und CLAUDE.md aus Unterordnern. Die kommen erst, wenn Claude eine passende Datei anfasst.
  • Antworten von Hooks. Ein eingerichteter Hook läuft zum Beispiel bei jedem Edit.

Bild für Subagenten: Ein Subagent ist ein Praktikant. Er liest einen Berg Dateien in seinem eigenen Zimmer und bringt dir nur eine Kurzfassung. Dein Schreibtisch bleibt leer. Aber die Arbeit des Praktikanten kostet trotzdem Usage.

6. Was /compact übrig lässt

Beim Aufräumen schreibt Claude euer Gespräch zu einer Kurzfassung zusammen. Einiges wird danach frisch vom Datenträger neu hingelegt, anderes geht in der Kurzfassung auf. (Docs: What survives compaction)

Kommt frisch wieder

  • deine CLAUDE.md im Projekt-Hauptordner
  • Regeln ohne paths:
  • die Memory
  • die Skill-Kurzbeschreibungen
  • bis zu fünf zuletzt benutzte Dateien (sehr große nur als Pfad)
  • Skills, die du aufgerufen hast, gekürzt

Geht in der Kurzfassung auf

  • euer Gespräch
  • Regeln mit paths:
  • CLAUDE.md aus Unterordnern
  • alle weiteren gelesenen Dateien

Regeln und Unterordner-CLAUDE.md kommen wieder, sobald Claude die nächste passende Datei anfasst.

Die Vorab-Frage: deine CLAUDE.md ist sofort wieder da.

Was du daraus machst

  • Soll eine Regel immer gelten, gehört sie in die CLAUDE.md im Hauptordner, nicht in paths: oder einen Unterordner.
  • Ein Skill wird beim Aufräumen von hinten gekürzt. Schreib das Wichtigste an den Anfang von SKILL.md.
  • Du kannst Claude sagen, was in der Kurzfassung wichtig ist: /compact focus on ...

7. Wann räumt Claude von selbst auf?

Sonnet 5.5 hat einen riesigen Schreibtisch (1 Million Tokens). Ohne Einstellung räumt es erst auf, wenn er fast voll ist, bei etwa 967.000. (Docs: Default auto-compact thresholds)

Setzt du in der settings.json "autoCompactWindow": 200000, räumt Claude nach den Docs schon bei 200.000 auf. (Docs: Set the auto-compact window) Dass das im Alltag wirklich so läuft: nicht beobachtet.
