Praktikant, Klon oder Kollege: wen schickst du los?

Du kannst Arbeit auf drei Arten abgeben: an einen Subagenten, an einen Fork oder an eine neue Session. Sie unterscheiden sich vor allem in zwei Dingen: was sie von eurem Gespräch wissen, und ob sie deinen Merkzettel mitbenutzen dürfen. Danach kannst du für eine Aufgabe sagen, welcher der drei am wenigsten kostet.

Vorab, aus dem Kopf
Deine Session läuft auf Opus. Du willst einen Fork losschicken, der auf dem billigen Haiku läuft. Geht das? Rate einfach. Die Antwort steht in Abschnitt 3.

1. Das Bild: drei Helfer

Stell dir vor, du arbeitest an deinem Schreibtisch (das ist deine Hauptsession). Neben dir liegt dein Merkzettel, der Cache aus Lektion 0001: Was darauf steht, muss Claude nicht teuer neu lesen.

  • Subagent = Praktikant im Nebenzimmer. Er bekommt einen Auftragszettel und arbeitet allein.
  • Fork = dein Klon. Er weiß alles, was du bis jetzt weißt, und arbeitet parallel weiter.
  • Neue Session = Kollege an einem anderen Tisch. Er hat seine eigene Aufgabe und bleibt, solange er gebraucht wird.

2. Der Praktikant (Subagent)

Ein Subagent startet mit einem leeren Schreibtisch. Er sieht euer Gespräch nicht, auch nicht die Dateien, die Claude schon gelesen hat. Er bekommt nur den Auftrag, den Claude für ihn schreibt, dazu deine CLAUDE.md-Dateien und den Git-Stand. Deine Memory bekommt er nicht. (Docs: What loads at startup)

Sein Merkzettel ist am Anfang leer, er kann deinen nicht lesen. Er baut sich während der Arbeit einen eigenen. (Docs: Subagents and the cache)

Sein Vorteil: Er darf ein billigeres Modell haben, zum Beispiel Haiku. (Docs: Choose a model) Und zu dir kommt nur seine Kurzfassung zurück, dein Schreibtisch bleibt aufgeräumt.

Sein Nachteil: Was er wissen muss, steht nur auf dem Auftragszettel. Ein schlechter Zettel heißt schlechte Arbeit, oder er muss sich alles selbst neu zusammensuchen.

3. Der Klon (Fork)

Ein Fork ist auch ein Subagent, aber er startet nicht leer. Er bekommt euer ganzes Gespräch, dieselben Werkzeuge und dieselbe Systemanweisung wie du. (Docs: Fork the current conversation)

Weil sein Anfang genau gleich ist wie deiner, darf er deinen Merkzettel mitlesen. Laut Docs ist ein Fork deshalb billiger als ein frischer Subagent, wenn die Aufgabe dasselbe Vorwissen braucht. (Docs: How forks differ)

Der Haken: Ein Klon ist eine genaue Kopie, also auch auf demselben Modell. Ein Fork aus einer Opus-Session läuft auf Opus, ein anderes Modell kann man ihm nicht geben. (Docs: How forks differ)

Die Vorab-Frage: Nein. Ein Fork läuft immer auf dem Modell deiner Session. Willst du Haiku, nimm einen Subagenten.

Noch zwei Dinge: Ein Fork kann keine weiteren Forks starten. Und nur sein Endergebnis kommt zu dir zurück, nicht seine Zwischenschritte.

4. Der Kollege (neue Session)

Eine neue Session ist ein ganz eigenes Gespräch. Sie weiß nur, was du ihr in den Auftrag (den Brief) schreibst. Sie lebt aber länger als ein Subagent, du kannst mit ihr reden, sie stoppen und ihr Ergebnis getrennt prüfen.

Für den Merkzettel zählt der Ordner. Zwei Sessions im selben Ordner können sich den Merkzettel teilen. Zwei Sessions in verschiedenen Ordnern, also auch in verschiedenen Worktrees, teilen nichts. (Docs: Cache scope)

Legst du für jede Session einen eigenen Worktree an, startet jede neue Session mit leerem Merkzettel.

5. Wie lange hält der Merkzettel?

Hier gibt es einen Unterschied, den man leicht vergisst. Der Merkzettel deiner Hauptsession hält auf einem Abo 1 Stunde. Der von Subagenten und Forks hält nur 5 Minuten. (Docs: Which TTL each request gets)

Eine neue Session ist wieder eine Hauptsession, also bekommt sie die Stunde.

Ob ein Fork, der deinen Merkzettel mitliest, ihn damit auch für dich frisch hält: nicht geprüft.

6. Wen schickst du los?

Frag dich zuerst: Wie viel von unserem Gespräch braucht die Aufgabe?

  • Fast nichts, viel Lesen oder Suchen: Subagent auf einem billigen Modell. Beispiel: "Such alle Stellen, wo X benutzt wird."
  • Sehr viel, und das Modell darf gleich bleiben: Fork. Beispiel: drei Lösungswege aus einem langen Gespräch parallel ausprobieren.
  • Eine eigene Sache mit eigenem Ergebnis (Branch, Commit), die länger läuft oder bei der du mitreden willst: neue Session.
  • Nur eine kurze Rückfrage zu etwas, das schon im Gespräch steht: /btw. Das hat keine Werkzeuge, und die Antwort bleibt nicht im Verlauf. (Docs: Choose between subagents and main conversation)

Eine Warnung aus den Docs: Viele Subagenten, die je einen langen Bericht abliefern, füllen deinen Schreibtisch trotzdem. Und jeder verbraucht beim Arbeiten eigene Usage. (Docs: Run parallel research)

Achtung Namen: Im Terminal startet /subtask einen Fork wie hier beschrieben. /fork kopiert je nach Einstellung die ganze Session in eine neue Hintergrund-Session. Wie die Desktop-App ihre Option "neue Session mit diesem Gespräch" technisch macht: nicht geprüft.
