Tools, Toys & Tinkering

  • Jakob's Agent Skills

    Agent skills I created from my own workflow and improved with every project. Some of them run through almost everything I do with AI. If one fits how you work, take it and adapt it.

    Installation: download a skill, drag it into your AI's chat and write "Install this skill."

    Handlers

    • /cheap-agents

      MD Decides if a helper agent is worth it, and which model is good enough

      Helper agents cost extra tokens, and someone has to check what they report. This skill makes the agent decide whether a helper is worth it at all, and pick the cheapest model that does the job well.

      If you did not ask for helpers, or it wants more than two, it first names the number, the models and a rough cost, and waits for your yes. It checks every report against the real files.

      Start it with /cheap-agents, or ask your agent to use helpers.

    • /lanes

      ZIP Keeps agent sessions from overwriting each other's work in one repo

      Agent sessions that change one git repository at the same time overwrite each other's work, causing lost changes and broken builds. This skill gives every agent session its own worktree and branch, keeps the main checkout clean and lands finished work there one branch at a time.

      A bundled script moves the main branch only when the full check on the merged result is green. Uncommitted work of other sessions stays untouched.

      The script needs Windows PowerShell and git, and is set up only after your yes. Start it with /lanes. Unzip it into your skills folder.

    • /fresh

      MD Spots when a session gets too long and hands the work to a fresh one

      The longer a session runs, the more context piles up, and the slower, costlier and less precise the agent gets. This skill carries your work over to a fresh agent session at a natural break, like a long conversation, a long pause, a new topic or a finished task.

      It writes a summary of the work so far, recommends a model and effort for the next session and offers to start it. The summary builds on Matt Pocock's fantastic /handoff skill, which writes one when you call it.

      It also works the other way round. When you continue from a handoff file, or after a crash or stop, it first checks the real state and lists what differs.

      Start it with /fresh. It also decides when it is time for a handoff. In Claude Code, an optional hook reminds it, set up only after your yes.

    • /now-and-then

      MD Remembers decisions and open points, so every session knows them

      Agents forget what you settled last week, so you explain the same name or rule again in every session. This skill records what you decide about a project in a dated log (DECISIONS.md) and keeps the current state and open points in a short second file (STATE.md), so every session starts from both.

      It writes a decision down the moment you state it. When you ask for something that contradicts an earlier decision, it stops and asks whether the decision changes. If your message already names the replacement, it records the change and goes ahead. Old entries stay readable, and both files are created or committed only with your yes. It never stores keys or personal data, and an entry never counts as permission to commit, deploy or delete.

      Start it with /now-and-then and say yes to the line it offers for your CLAUDE.md or AGENTS.md. Without that line it rarely starts on its own.

    • /touch-grass

      MD Works through your plan alone while you are away, then reports back

      When you step away, an agent normally stops at its next question and the session waits for hours. This skill lets the agent work through your existing plan alone to the end, answer each open question with its own recommendation, skip what only you can decide, and finish with a colour-coded report.

      Every decision becomes its own small commit with a log entry that says how to undo it. Deleting what has no backup, pushing, publishing, spending money and signing in wait for you. Deploys wait too, unless your project instructions allow them while you are away. A failing step gets three different attempts, then it is reported as failed.

      The report sorts every decision by colour: orange needs you, red failed, yellow means other work builds on it, green is easy to undo. Each line names its commit, so you can simply say "undo number 3".

      Start it with /touch-grass, or tell your agent you are away for a while. Where your app offers the tools, it keeps the machine awake and sends a notification at the end.

    • /am-i-done

      MD Checks whether the whole task is finished before you close the chat

      Closing a chat is easy; knowing nothing is left behind is not. This skill checks the whole task, not just the last step: every request you made in the chat, the sessions it started, the session that started it, other parts of the same series, and the git and deploy state.

      It answers with a colour: green means you can close the chat, orange means nothing open was found but not everything could be checked, red comes with the list of open points. It only reads and never fixes or archives anything.

      Start it with /am-i-done, or ask "can I close this chat?". The other-session checks need the session tools of the Claude desktop app; elsewhere it checks the conversation, git and your notes files and says what it could not check. It has not yet been run against real multi-session setups.

    Fixers

    • /workaround

      MD Finds another route when the direct one is blocked

      AI agents sometimes keep running into the same wall. This skill finds another way to your goal when something outside your control blocks the direct one, like a failing tool or a missing feature.

      It stops at permission and security checks, and asks before system-wide changes or before deleting something that can't be restored.

      Start it with /workaround.

    • /reroll

      MD Asks again in a new chat that never saw the first answer

      Ask again in the same chat, and the new answer is shaped by the old one. This skill hands your request, word for word, to a new session that has never seen the rejected answer.

      /reroll 2 or /reroll 3 starts that many attempts in parallel, /reroll different asks for less obvious choices, and a model name such as /reroll sonnet picks the model.

      Outside the Claude Code desktop app, you paste the prompt into a new chat yourself. Start it with /reroll, or say "reroll" or "ask a fresh chat".

    • /unrobot

      ZIP Makes a text read as if a person wrote it

      Machine-written text gives itself away: grand closing lines, inflated significance, brochure tone, em dashes. This skill finds those marks in a text, a file, a folder or a whole site and rewrites the passages so they read as if a person who knows the subject wrote them.

      It builds on the Wikipedia article "Signs of AI writing" and leaves wording you fixed on purpose alone. Its scanner needs Python 3 and reads English only.

      Start it with /unrobot, or ask to make a text "sound less like AI". Unzip it into your skills folder.

    Cleaners

    • /strays

      MD Finds commits you never pushed, and pushes them after your OK

      Work you committed but never pushed is easy to forget. This skill finds git commits that never reached the remote, on a side branch, the wrong branch or in a worktree, and shows them in one table before anything is sent.

      It pushes only after your OK and never by force. Diverged branches and uncommitted changes are left to you.

      Start it with /strays, or add "push everything" to skip the question.

    • /freeup

      ZIP Frees disk space on Windows drives, deletes only what you approve

      Windows slowly fills the system drive with caches and temp files nobody needs. This skill measures the junk on your drives, shows you a size table and deletes the rows you approve with one yes. In folders you name, it also finds duplicate files, archives that sit next to their extracted folder and the biggest files.

      Caches and temp files that programs rebuild go after one yes. Your own files go only by the numbers you pick from the list, and duplicates are proven identical by checksum first. Files in use stay.

      Windows only. Start it with /freeup, or ask for space or for duplicate files. Unzip it into your skills folder.

    • /tidy-sessions

      MD Archives finished sessions in Claude Code Desktop, keeps the rest

      Finished sessions pile up in the sidebar. This skill archives your finished sessions in the Claude desktop app and keeps every session with unfinished work.

      It reads how each session ended and checks in git that its branch has landed and its worktree is clean. It never deletes a session and lists what needs your attention.

      Only for the Claude desktop app (Code tab). Ask it to tidy your sessions, or which ones would be archived.

    • /tidy-worktrees

      MD Removes worktrees and branches that have landed, keeps the rest

      Old worktrees and branches pile up, and it is hard to tell which ones are safe to delete. This skill removes only the git worktrees and branches whose work has landed in the default branch and whose worktree is clean, and keeps everything else.

      It never pushes or forces a removal, and leaves locked worktrees and the one you are in alone.

      Start it with /tidy-worktrees, or ask which worktrees would be removed. It needs git 2.31 or newer.

    • /fingerprints

      ZIP Checks a folder for names, paths and keys before you share it

      A folder you share can carry your name, a home folder path or a key without you noticing. This skill checks a skill, repository, project or site before you share it and lists what to fix: private words you give it, absolute and home paths, email addresses, keys and tokens.

      It changes nothing unless you ask for fixes. It does not read the git history and is not a full secret scanner.

      It needs Python 3. Start it with /fingerprints, or ask whether a folder is safe to share. Unzip it into your skills folder.

    Detectives

    • /blindfold

      ZIP Blind test: is the changed prompt really better?

      It is easy to believe a rewrite helped and hard to know. This skill runs a blind, counted test of whether a changed prompt, skill or agent does better than the old version and than none at all, or a calibrated audit of many texts by blind readers.

      The right answers are fixed before any answer is read, and two judges score without knowing which version wrote what. You hear the setup, its weaknesses and the cost first, and nothing starts before your OK.

      Start it with /blindfold. Unzip it into your skills folder.

    • /numbers-skeptic

      MD Makes your agent measure claims like faster, smaller or unused

      Agents like to report that something is now faster, smaller or unused after one run, or after none. This skill has the agent measure every claim about speed, size, share, ranking or unused code in your software, and mark what it could not measure as "not checked".

      For timings it checks the machine's load, warms up, repeats the run, and gives the median and the spread. A result counts as reproduced only after a second, separate series, and a difference smaller than the noise counts as no difference. Values come from the running app and never from a test fixture. Before it calls code unused, it searches code, tests, config, scripts and docs for it.

      It needs a shell. It changes no system settings, does not repeat commands that deploy, send or call a paid or shared service, and does not review other people's reports. Careful measuring takes longer than guessing.

      Start it with /numbers-skeptic, or ask whether something really got faster, smaller or is unused.

    • /measure-ui

      MD Checks a web page with measured numbers instead of by eye

      A layout can look fine in one screenshot and still overflow on a phone, or break when you switch tabs and back. This skill has the agent set the viewport first, read sizes and positions from the running page as numbers, switch between items in more than one order and report what it did not check.

      It needs a real browser the agent can run JavaScript in. It never signs in and never changes data.

      Start it with /measure-ui, or ask whether a layout works on a phone.

    • /media-review

      ZIP Checks generated images, audio and video against your brief

      A good prompt does not guarantee a good result. This skill checks images, audio and video that another model made against your requirements, measures the actual files, and tells you up front which parts only your eyes or ears can judge.

      Before a paid or slow run, it tells you the cost, waits for your yes and starts with one small sample. Every failed asset is named with the requirement it missed.

      The image check needs Python. Start it with /media-review, or ask whether a generated result is good enough. Unzip it into your skills folder.

    • /nothing-lost

      ZIP Backs up before a big rewrite, then checks that no line got lost

      Big rewrites lose words and numbers without anyone noticing. This skill makes the old state recoverable in git first, moves text word for word, and then has a script check that every old line still exists in the new files.

      It lists every line found nowhere and marks lines that changed on purpose. Line order and counts are not checked.

      It is meant for about 5 or more files, or 100 or more lines, and needs Python 3 and git. Start it with /nothing-lost, or say that nothing may get lost in a rewrite. Unzip it into your skills folder.
