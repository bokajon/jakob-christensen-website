---
name: reroll
description: Rerolls the last answer blind by handing the user's own request word for word to a brand-new session that has never seen the rejected answer. Use with /reroll, or when the user says "reroll", "ask a fresh chat" or "try again without seeing your answer", or wants an unanchored second attempt at an answer they disliked (ideas, brainstorm, tips, a plan). Not for fixing a factual error in the answer (just fix it) and not for continuing work.
compatibility: Starts a separate session through the Claude Code desktop app's start_session tool. In any other tool it copies the prompt to the clipboard (shell) or prints it, and the user pastes it into a new chat.
---

# Reroll

Goal: give the user a second attempt at their own request from a brand-new session that has never seen the rejected answer. This session only copies and never answers the request itself, also when the request came in as the skill's arguments. Anything it writes about its earlier answer is already coloured by that answer, so it never summarizes, rephrases or comments on it.

Arguments (all optional, any text after `/reroll`, any language):
- A model name (`sonnet`, `haiku`, `opus` or a full model id) sets the new session's model (pass the full current id of that model, as the environment info names it). Default is the current model. `start_session` only accepts the same or a cheaper model and ignores a higher one. If the user asks for a higher model, use the copy route of step 4 and say why in one line, never start a weaker session silently.
- `2` or `3` starts that many independent blind sessions in parallel. It counts only as a bare number right after `/reroll` (or after the model name) that is not part of a request in the same message (`/reroll 3 names` is a request, `/reroll 3` is a count), and only when the user typed it. Without it (also when the skill was invoked by the model, not by `/reroll`) start exactly 1. A higher number is capped at 3 and the reply says so. All get the identical prompt.
- `different` (also "anders"), as the first word after `/reroll` (or right after the count or model name), tells the new session that an earlier answer existed and was rejected, never what it said. Without the word the new session gets no hint of an earlier answer.
- Any other text goes into the request as the user's own words under a line `Additional note from me:`.

1. Pick the text to hand over. Only the user's own words go, verbatim.
   - Normal case: the last user message before this command that is not itself a `/reroll` call, including pasted blocks and file paths. If the `/reroll` message also holds the request (`/reroll 5 name ideas`), that request is the text to hand over, minus the arguments.
   - If it refers to earlier context ("do that for the game", "the same for B"), add the earlier user messages it depends on, in order.
   - If the last message was only a reaction (a "yes", "again", a click in a question box), walk back to the user message that asked for the rejected answer and hand over that one, plus the context above if needed.
   - If the request cannot be understood without assistant text (the user's "B" answers the assistant's options), ask once, quoting exactly the assistant sentences that would go along, and offer to send without them. This is the only case where the skill asks before acting.
   - If the message is no longer verbatim in context (compaction or summary), recover it from the saved transcript of this session only (Claude Code: the app's transcript export tool, or the most recently modified `.jsonl` file in this project's folder under `projects` in the Claude config directory, after checking that it matches this conversation). If it cannot be recovered verbatim, say so and ask the user to paste it. Never rebuild it from memory.
   - Images and attachments cannot be passed. If one exists as a file, put its path into the handed-over text; otherwise say in the reply which image or file the user must add again in the new session.
   - If this session was itself started by `/reroll`, strip the `[reroll]` footer first so the wrapper is never doubled.
2. Leak check. Files the rejected answer created or changed go into the do-not-open list of the prompt. Take them from this session's own tool calls in that answer, wherever the files are, and in a git repo add what `git status --short` shows from shell commands. If it cannot be told reliably which files the answer wrote (for example after compaction), leave the list out. A chat-only answer gives an empty list, which is left out. Never write anything about the request or the earlier answer into a shared notes folder the app offers for linked sessions.
3. Build the prompt:
```
<the user's request, verbatim; several messages separated by a blank line, "---" and a blank line>

[reroll] This request was handed over by /reroll from another session. Answer it as the first message of this conversation. Do not read or search session transcripts or other sessions (no transcript search, export or event tools, no session transcript files such as the `.jsonl` files in the Claude config directory's `projects` folder). Do not message other sessions and do not read the shared side-session notes folder. <with `different` only: An earlier answer to this request was rejected by the user, its content is deliberately withheld. Avoid the most obvious choices.> <if the list is not empty: Do not open these files, they hold the earlier answer: `a`, `b`.>
```
4. Start the session(s).
   - Claude Code desktop (tool `start_session`, load it first if it is deferred): call it with `initiation: "user_asked"`, `context: "fresh"`, `use_worktree: false` (if the tool refuses that here, call it again without `use_worktree`), `title: "reroll: <topic in 3-5 words>"`, `model` only if the user named one, and the prompt from step 3. `background` (required, at least 80 characters) is always exactly this text, also with `different`: "The user wants an independent answer to the request in the prompt, written without knowledge of any earlier attempt. Work in this project folder with the usual project rules." It holds no assistant text. If the tool's parameters differ from these or the call fails, use the copy route below and say so in one line. For a count of 2 or 3, make that many identical calls in one message, titled "reroll 1/3: <topic>" and so on.
   - Anywhere else (Codex, a CLI without that tool, claude.ai, another chat app): with a shell, put the prompt on the clipboard (Windows `powershell.exe -NoProfile -Command Set-Clipboard`, macOS `pbcopy`, Linux `wl-copy` or `xclip -selection clipboard`) and say "Copied. Open a new chat and paste it." Without a shell, or if the clipboard command is missing or fails, print it in one fenced block and say "Open a new chat and paste this block." With a count of 2 or 3 here, copy or print the prompt once and add "Paste it into 3 new chats." (the number asked for). Never claim a session was started when none was. Say "Copied" only when the clipboard command ran and succeeded.
5. Reply in the old session with at most three short lines in the user's language (the handed-over text itself does not count toward the lines): the link to each new session (desktop: `[title](#local_<id>)`, id from the tool result), the exact text handed over in a collapsed or fenced block, and any note (image to re-paste, model or count capped). Unless the user already gave `different` or a model, end with the tip "For more variety: `/reroll different`, or name another model, e.g. `/reroll <a model cheaper than the current one>`." (the same model with the same prompt tends to return the same ideas). No comment on the earlier answer, no comparison, no apology. Do not archive or close the old session.

Done when every requested session is started (or the prompt is on the clipboard or printed) and the reply holds the link or instruction plus the handed-over text.
