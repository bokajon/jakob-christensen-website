## Image script (2026-11-24, Jakob said yes, built on branch claude/media-review-script from the unintegrated media-review branch)
- Added `scripts/check_image.py` and step 4 now points to it. Standard library only for format, width, height, ratio, file size and "has an alpha channel" (PNG, JPEG, GIF, WebP headers). Pillow is optional: it adds the real transparency check, distinct colors and dominant colors. Without Pillow those lines say NOT MEASURED. Options are requirements and give PASS, FAIL or NOT MEASURED; exit 0, 1, 2 (unreadable), 3 (nothing failed, something not measured).
- "Transparent" passes only if the file has an alpha channel and all four corner pixels are fully transparent. A declared alpha channel alone gives NOT MEASURED without Pillow, never PASS. Identical files (SHA-256) are reported: the earlier headless test showed two generations that were identical but not noticed.
- Tested: `python -I tools/test_check_image.py`, 26 cases, 0 failed (hand-built PNG, JPEG, GIF, WebP headers, Pillow hidden and visible, wrong and right requirements, identical, unreadable, usage). On 3 real images from the site (2 PNG, 1 WebP) the sizes and formats equal what Pillow reports (192x224, 412x480, 453x174). The pixel numbers (corners, colors) were not checked against a second tool. `check_skill.py` and `fingerprints.py --no-dashes` on the folder: OK.
- Not tested: the skill with the script in an agent run (no headless run, so whether an agent calls it and reads the exit codes correctly is open), big images over 4 million pixels for the color count (returns NOT MEASURED by design, not exercised on a real file), animated GIF or WebP, JPEG with the size marker after 4 MB of header data (returns unreadable), Python versions other than 3.15 on this machine, macOS and Linux.
- Not done: no audio or video script, no ZIP, no card text, nothing published or put on the site.

## Image script in an agent run (2026-11-24, Claude Code headless, Sonnet, `/media-review`, 1 counted run)
- Setup: throwaway folder with `.claude/skills/media-review` (copy of the draft incl. `scripts/check_image.py`) and `gen/` with `ok.png` (512x512 RGBA, transparent corners, 2 colors, 2794 bytes), `bad.png` (512x384 RGB, no alpha, 1430 bytes), `big.png` (2100x2100 RGBA, 18225 bytes, over 4 million pixels), `broken.png` (PNG signature plus text, 24 bytes), `bad_copy.png` (byte copy of `bad.png`, not named in the prompt). Requirements: PNG, under 50 KB, transparent, at most 16 colors; 512x512 for ok, bad, broken. Each image to be checked on its own with exit codes named. Python 3.15.1, Pillow 13.0.0.
- First attempt (`--allowedTools "Bash" "Read"`): the agent used the PowerShell tool, python was denied, so the script never ran and it fell back to hex dumps (same blocker as in the second retest). Not counted. Second attempt with `--allowedTools "PowerShell(python:*)" "PowerShell(python *)" "Read" "Glob"`: python allowed.
- Result: the agent found the script by Glob (`**/check_image.py`), read it once, and called it by its relative path as `python -I ...check_image.py <file> --format png --max-bytes 50000 --transparent --max-colors 16 [--size 512x512]`, one call per image. Output matches the script: ok.png exit 0, 5 PASS lines, 0 failed. bad.png exit 1, FAIL size (512x384) and FAIL transparent (no alpha channel), 3 PASS. broken.png exit 2, "unreadable: not a PNG, JPEG, GIF or WebP file". big.png exit 3, PASS max-bytes, format, transparent, NOT MEASURED max-colors (over 4000000 pixels). Its summary table gives all four exit codes right and keeps the judged part apart: it viewed the images and said the content of big.png (one green square on a huge canvas, not a sprite sheet) is a judgment, not a measurement. It also named the unmentioned `bad_copy.png` and offered a duplicate check.
- Caveats: exit 1, 2 and 3 were read from the tool's "Exit code N" error text; exit 0 was inferred from the absence of that text (reading `$LASTEXITCODE` was blocked in that sandbox), which happened to be right. The duplicate-file line of the script was not exercised because the agent skipped `bad_copy.png`. Whether `/media-review` really loaded the skill is not checked (a `/name` start leaves no trace in stream-json), but the agent used the script path and the PASS, FAIL and NOT MEASURED wording that only the script prints. One run, one fixture: weak evidence. Still not tested: animated files, JPEG with a late size marker, other Python versions, macOS, Linux, Windows without Pillow (exit 3 was only seen via the over-4-MP path).
